# AI 助手 / 智云 / AI.Super Agent —— 开发项目梳理报告

> 梳理日期：2026-08-25
> 依据：本目录全部 4 个 EXE + 9 份工程文档的实际内容核对（非仅看文件名）
> 结论先行：这是**一个产品**，不是三个项目；当前最大的问题是**命名反复 + 文档重复冲突 + 文档架构与真实产物不符**。

---

## 1. 一句话结论

`G:\ai\软件开发工程\AI助手` 里只有**一个本地优先的 Windows 桌面 Agent 应用**，技术形态是：

- 前端：**零构建** React UMD + 原生 ES Module（`webroot/js/agent.js` 为真正生效的引擎，1292 行）
- 后端：Python 标准库 `http.server` 本地托管 + `pywebview` 弹窗（缺 WebView2 回退浏览器）
- 打包：PyInstaller 6.20.0 `--onefile --windowed`，约 43.3 MiB 单文件 EXE

它经历了一轮**命名漂移**（AI助手 → 智云 → AI.Super Agent）和**文档爆炸**（v1→v4 四版 + 两份互相矛盾的"集成/权威"总册）。代码本身不在这个目录，也不在本机可达路径（见 §5）。

## 4. 最危险的事实偏差：文档架构 ≠ 真实产物

| 维度 | v1–v4 文档描述的"设计"（TS 系） | 真实交付产物（零构建系） |
|---|---|---|
| 前端语言 | TypeScript（Vite + React + `src/agent.ts`） | 纯 JavaScript（React UMD，`webroot/js/agent.js`） |
| 构建 | `npm run build` → `dist/` | 无打包，直接 `webroot/` 静态目录 |
| 引擎入口 | `src/agent.ts` | `webroot/js/agent.js`（1292 行，命令/记忆/Skills/MCP/云端/流式全在里面） |
| 冻结到 EXE | `--add-data dist;webdist` | `--add-data webroot;webdist`（一致） |

**对后续维护者的致命提示**（摘自交付文档原话）：
> 源码仓库里的 `src/*.tsx` 是「参考/归档」性质，**不是构建入口**，升级时**不要误改 `src/` 而忽略了真正生效的 `webroot/js/`**。

也就是说：如果你（或接手的开发者）照着 v1–v4 文档去改 `src/agent.ts`，**改了也不会生效**。所有改动必须落在 `webroot/js/` 下。
